01

Start · why this matters

課程核心觀念與講義使用方式

AI 找得快，不代表找得完整。你真正要帶走的不是某個工具的按鈕位置，而是能被記錄、測試、回查與說明的工作方法。

速度不能代替完整性 Lau 與 Golder（2025）以四個證據綜整案例比較研究中使用的 Elicit Pro Review mode 與原始回顧的傳統搜尋：平均 sensitivity 分別為 39.5% 與 94.5%。這只代表該研究設定與工具版本，不能概括所有 AI 工具；它提醒我們評估的是遺漏相關研究的風險，而不只是操作速度。
閱讀原始研究
AI 可以協助
  • 整理 PICOS 候選與待確認問題。
  • 擴充關鍵字、MeSH 候選與檢索式初稿。
  • 搜尋、排序、摘要與關聯文獻探索。
  • 依標準做題名摘要初篩並留下理由。
研究者必須負責
  • 確認研究問題、納排標準與範圍。
  • 核對 MeSH、資料庫、檢索式與結果數。
  • 回到原始文獻查核書目、研究設計與結果。
  • 作成最終納入／排除決定並揭露 AI 用法。

使用這份講義的方式

  1. 先用目錄找到目前的任務，不必從第一頁讀到最後。
  2. 依章節完成「人先決定」與「AI 可協助」的分工。
  3. 到最後一章複製 Prompt，替換括號內資訊後再送出。
  4. 保存工具、版本／方案、使用日期、資料來源、Prompt 與人工修訂紀錄。
核心句AI 可以協助發現與整理文獻；證據仍來自原始研究，最終決策仍由研究者負責。
02

5A · task before tool

5A 流程與人工查核原則

選工具前先問：我現在位於 5A 的哪一階段？我要的輸出是候選問題、可重現檢索、文獻關係、全文定位，還是來源限定比較？

完整證據路徑問清楚 → 找方向 → 正式找全 → 篩選整理 → 閱讀核對。Prompt 是各步驟共用的操作語言；資料庫與人工決策是可重現主幹。
5A 階段目前任務本課優先工具人工查核點
Ask聚焦問題、理解臨床脈絡OpenEvidence；通用 LLM定義 PICOS、回原始指引與研究
Acquire搜尋、發現與延伸文獻PubMed／Connector、Consensus、Elicit、Connected Papers回 DOI／PMID、資料庫與全文核對
Appraise定位原文、整理研究欄位SciSpace；Elicit 輔助整理核對支持句、效果值、時間點與分母
Apply依已選來源做整合與應用Gemini Notebook確認來源適切性並逐格點回引用
Assess評估成效、偏差與可重現性研究者主導；AI 協助整理保留版本、紀錄與人類決策

固定使用的三個判斷句

Task

我要解決的是哪一個任務？

Trace

工具的資料來源與輸出能否查核？

Human

最後哪一步必須由人做決定？

通用 LLM（例如 Claude、ChatGPT、Gemini）可橫跨 5A 協助表述、改寫與結構化，但不等於專用資料庫或系統性檢索平台。同一工具也可能跨越多個階段；本講義標示的是課程優先用法，而非產品完整功能表。

不要把產品功能與 EBP 流程混在一起資料庫仍是可記錄、可測試、可重現的主幹；AI 工具只加速其中的特定任務。
03

Ask · define before searching

從臨床觀察建立 PICOS

先讓 AI 提出候選與追問，不讓它替你把研究範圍定案。每一欄都要區分已知資訊、合理候選與待確認事項。

共同案例 成年 ICU 病人常因重症狀態、睡眠中斷與環境改變發生譫妄。團隊想知道：家屬參與照護或較彈性的探視方式，是否能降低住院期間譫妄？
元素本案例候選需要再確認
P成年 ICU 病人ICU 類型、年齡界線、特殊族群
I家屬參與照護／彈性探視兩者是否合併、介入強度與內容
C常規照護、標準或限制探視比較組定義是否需要收窄
O譫妄發生率；次要可看持續時間、嚴重度或無譫妄天數主要與次要結果的優先順序
S優先 RCT主檢索式先不加設計限制，搜尋後再篩

為什麼 C 與 O 不一定放進主檢索式？

比較組在題名與摘要中可能沒有被清楚描述；結果用詞與索引方式也較多元。過早把 C 或 O 放入主檢索式，可能讓策略太窄。先用核心概念搜尋，再於篩選階段判斷，通常較能降低漏失風險。

好的 Prompt 要交代五件事

背景

角色、臨床情境、已有資料。

任務

只交付目前這一步。

限制

來源、範圍與禁止猜測。

輸出

表格欄位、理由與引用。

不確定性

資料不足寫待確認。

完整可複製版本請見 Prompt 1｜臨床觀察 → PICOS。

04

Terms · candidate is not confirmed

從 PICOS 建立 MeSH 與自由詞

MeSH 不是靠 AI 猜答案。AI 可以產生候選詞，但正式 Heading、Scope Note 與 Entry Terms 都要回 NLM MeSH Browser 核對。

Prompt 要約束 AI
  • 一個概念一列，MeSH 與自由詞分開。
  • 所有 MeSH 標示「候選／待核對」。
  • 不要捏造 Scope Note、Entry Terms、結果數或文獻。
  • 可能歧義的詞另列，不直接放入正式策略。
官方核對四項
  1. 正式 Heading 是否存在。
  2. Scope Note 是否符合研究語意。
  3. Entry Terms 能補哪些自由詞。
  4. 最後決定採用、修正或不用。

本案例的三個主要概念塊

概念MeSH 候選自由詞候選查核提醒
ICUIntensive Care Unitsintensive care unit、ICU、critical care核對 Heading 與複數形式
家屬參與／探視Familyfamily participation、family involvement、family engagement、family-centered care、flexible visitation、family visitationFamily 是否足以代表介入，需看 Scope Note 與搜尋結果
譫妄Deliriumdelirium、ICU delirium確認結果詞是否讓策略過窄
「有這個 MeSH」不等於「適合這個問題」先看 Scope Note，再決定是否放進檢索式。

開啟 NLM MeSH Browser｜完整可複製版本請見 Prompt 2｜PICOS → 關鍵字與 MeSH 候選。

05

Search · build, test, diagnose

建立並實測 PubMed Search Strategy

同義詞用 OR 串接，概念塊用 AND 組合。真正重要的不是 AI 產出一條看似完整的字串，而是你能逐塊測試、記錄結果並診斷漏失。

("Intensive Care Units"[Mesh] OR "intensive care"[tiab] OR ICU[tiab] OR "critical care"[tiab])
AND
("Family"[Mesh] OR "family participation"[tiab] OR "family involvement"[tiab] OR "family engagement"[tiab] OR "family-centered care"[tiab] OR "flexible visitation"[tiab] OR "family visitation"[tiab])
AND
("Delirium"[Mesh] OR delirium[tiab] OR "ICU delirium"[tiab])

1｜指定資料庫

本堂示範 PubMed。換到 CINAHL、Embase 或 Cochrane Library 時，主題詞、欄位代碼、截詞與語法都需重寫。

2｜核對語法

檢查欄位標籤、引號、括號與 AND／OR 是否正確。

3｜核對結果

記錄執行日期與結果數，確認已知種子文獻是否出現。

4｜診斷漏失

找不到已知文獻時，從三塊退回兩塊、單塊，定位過窄概念。

逐步測試順序

  1. 分別執行 ICU、家屬參與／探視、譫妄三個單一概念塊。
  2. 測試 ICU AND 家屬參與／探視。
  3. 再加入譫妄概念塊。
  4. 找不到已知種子文獻時，逐塊移除並檢查題名摘要實際用詞。
  5. 日期、語言、Humans 或研究設計限制留到策略穩定後再測。
日期限制用介面操作較不易出錯年限可在 PubMed 左側 Publication date 勾選 1／5／10 years，或使用 Custom range；不必每次重打整條檢索式。

開啟 PubMed｜完整可複製版本請見 Prompt 3｜建立可實測的 PubMed 檢索式。

06

Verify · connector is not the database UI

Connector 與 PubMed 官網核對

Claude 的 PubMed Connector 能把檢索真正送到 PubMed 並回傳 PMID，但它是加速前期探勘的入口，不取代 PubMed 官網的完整介面與正式搜尋紀錄。

層次作用本課怎麼用
網站／資料庫介面完整欄位、filters、歷史紀錄與匯出PubMed 官網負責正式實測與保存
Connector在 AI 對話中呼叫外部服務快速執行並帶回候選與 PMID，再回官網核對
MCP讓 AI 連接工具與資料的標準協定是連接方式，不是資料庫，也不保證搜尋完整性

確認 Connector 真的被呼叫

  1. 在 Claude 輸入框附近開啟 Connectors，加入並開啟 PubMed。
  2. 送出清楚的資料庫任務，要求保留 search strategy 與 PMID。
  3. 回答過程應出現工具呼叫區塊；展開後核對實際 query 與回傳 PMID。
  4. 沒有工具呼叫區塊時，不要把模型生成的回答當成資料庫結果。

查詢有複雜度上限

字串太長、同義詞太多或布林結構太複雜時，連接器可能拒絕、簡化或重新解析。

功能不是完整介面

缺少完整 filters、排序、My NCBI 與 RIS／EndNote 匯出能力。

字串可能被重新轉譯

連接器解析後送出的 query 可能與你貼入官網的字串不同，必須展開工具區塊核對。

筆數可能截斷

單次回傳有上限，重跑也未必完全一致；正式結果以官網為準。

核對流程

把 Connector 實際送出的 query 複製到 PubMed 官網，記錄執行日期、完整策略、官網結果數與已知種子文獻是否出現。本案例可用 Rosa et al.（2019）作為已知文獻：PMID 31310297，DOI 10.1001/jama.2019.8766。

正式原則AI 端做前期探勘；正式檢索回資料庫官網重跑，保存完整查詢式、執行日期、結果數與匯出檔；截圖僅作輔助。

可複製的 Connector 任務與官網檢索字串收在 Prompt 工具箱。

Explore · different tools answer different questions

核心工具、支援工具與延伸資料

工具不是平行的網站清單。核心工具承接課堂主流程，支援工具補 citation chasing 與來源限定整理；Asta 因時間因素移至 Bonus 延伸。

工具本課主要任務適合帶回家的用法人工查核提醒
OpenEvidenceAsk：醫療版 AI 搜尋引擎＋evidence synthesis把偏寬問題問清楚，追到 guideline 與原始證據入口核對組織、年份、族群與原文；不等於完整系統性搜尋
ConsensusAcquire：自然語言快速掃描理解研究方向、取得候選 papers 與引用摘要、Meter 與 Graph 都是探索入口；回 DOI／PMID／全文
ElicitAcquire／Appraise：語意搜尋與欄位化確認核心研究、補充候選、比較欄位欄位空白不等於不符合；screening 與 extraction 回支持句核對
Connected PapersAcquire：從可靠種子文獻延伸探索 Similar、Prior、Derivative works相似性圖譜不是完整 citation tree，也不等於系統性檢索
SciSpaceAppraise：Chat with PDF在指定全文定位方法、結果與支持段落生成表格不是正式資料萃取；核對頁碼、單位、時間點與分母
Gemini NotebookApply：來源限定跨文件比較只依已選 PDF／文件建立比較表先確認上傳來源適切，再逐格點回 inline citations

四種「找文獻」方式回答不同問題

可重現檢索

PubMed／Connector

依明確策略找出哪些紀錄？正式 Acquire 主幹仍是資料庫。

語意相關性

Elicit

哪些研究和我的問題語意最接近？適合找核心文章與補充候選。

文獻關係

Connected Papers

從可靠 seed 往相似、先前與後續研究怎麼走？屬於 citation chasing／other methods。

快速理解

Consensus

研究大方向與候選證據是什麼？用來掃描並形成下一步追問。

整合句不是誰取代誰，而是「可重現資料庫檢索」加上「AI 探勘／延伸」；所有候選文獻最後都回 DOI／PMID／原文核對。

功能核對日期本章依主簡報於 2026-08-30 整理的官方功能地圖重整；介面、方案與功能可能持續更新，實際使用前請再查看官方說明。

08

Screen · evidence for every decision

篩選、全文閱讀與資料彙整

AI 初篩最重要的不是「替你選完」，而是逐筆保留 P／I／C／O／S 判斷、單一主要理由與支持原文，讓研究者能抽查、處理衝突與重新判定。

納入

摘要可支持主要條件；仍需全文確認。

待確認

資料不足、語意含糊或需全文判斷；不能因沒寫就排除。

排除

至少一項納入條件明確不符，並寫出單一主要理由。

AI 初篩後，人要查三層

  1. 書目身分：題名、作者、年份、期刊、PMID／DOI 是否一致；是否為重複紀錄。
  2. 納排依據：AI 的理由是否真的出現在題名或摘要；「沒提到」不等於「不符合」。
  3. 研究設計與全文：protocol、review、RCT、觀察性研究要分清，必要時回全文。
三種高風險情況工具沒有檢索到的研究不會進入後續人工視野；錯誤排除需要靠保留完整紀錄與理由補救；引用／摘要錯配必須以 DOI／PMID 回原始頁確認。

全文閱讀：AI 先定位，人再核對

單篇 PDF｜SciSpace

指定欄位與問題，要求每一點附頁碼、段落或支持句；沒有報告就寫「未報告」。

多篇已選來源｜Gemini Notebook

限定只依上傳來源建立比較表；每一格附來源，不加入外部知識。

建議欄位包括：研究設計、場域、樣本與特徵、PICOS、介入細節、比較組、結局與時間點、效果估計、95% CI／p 值、不良事件、作者陳述的限制，以及每一項的原文位置。

摘要不是全文AI 產生的結構化表格也不等於資料萃取完成。每個效果值、單位、時間點與分母都要回原文。

可複製版本請見 Prompt 4｜題名摘要初篩 與 Prompt 5｜全文閱讀與資料彙整。

Report · make human and AI roles visible

PRISMA、方法揭露與 Agent

AI 用在哪一步，會影響 PRISMA 的紀錄位置與 Methods 的寫法。先判斷紀錄從哪裡來、誰作最後決定，再決定如何報告。

AI 使用方式PRISMA 紀錄原則必須保存
AI 協助建立檢索式，實際在資料庫執行紀錄仍放在實際搜尋的資料庫；AI 用法寫入 Methods資料庫、策略、日期、結果數、工具與人工修訂
AI 工具直接找文獻或追蹤引文依實際來源列於 websites、organizations、citation searching 或 other methods工具、種子文獻、日期、找到的紀錄數與去重方式
工具在人工篩選前直接排除可列為 records marked as ineligible by automation tools門檻、排除數、抽查與風險控制
AI 排序或初判，研究者確認記入一般 screening／exclusion 流程人工複核方式、衝突與最終決策

PRISMA-trAIce 的位置

PRISMA 2020 已要求報告自動化；PRISMA-trAIce 進一步將人與 AI 的處理量、決定與理由拆成獨立欄位，並區分規則型行政工具與做納排判斷的評價型 AI。它是經同儕審查發表的基礎提案，但不是 PRISMA 官方擴充指引，投稿仍需以目標期刊規定為準。

Methods 揭露範本

本研究於〔實際階段〕使用〔工具名稱／版本或方案〕（使用日期：〔YYYY-MM-DD〕），用途為〔具體任務〕；提示詞見〔附錄／補充資料〕。
工具輸出由〔實際人數與複核方式〕查核；歧異以〔實際處理方式〕解決。最終納入與排除決定由研究者作成。

揭露至少包含：工具、版本／方案、使用日期、實際用途、Prompt 保存位置、人工複核人數、複核方式與衝突處理。

任務型 AI Agent：串接，但不越權

  1. 輸入 PICOS：人先定義問題與核心檢索概念。
  2. 產生候選詞：AI 建議 MeSH、同義詞與 truncation；人核對取捨。
  3. 多來源搜尋：從資料庫與學術來源取得候選紀錄。
  4. 整理與匯出：去重、題名摘要初判、輸出 CSV／RIS／數字摘要。
  5. 回到人類篩選：匯入 Rayyan 等平台，處理盲化篩選、排除理由與 conflicts。
較精確的名稱「任務型 AI Agent」或「人機協作的半自動文獻代理流程」。它不是能自主完成系統性回顧的通用代理。

11

Reuse · copy, adapt, verify

完整 Prompt 工具箱

下列內容可直接複製，再依自己的臨床問題與資料來源調整。複製 Prompt 不等於複製結果：每次仍需保存工具、版本、日期、輸入來源、人工修訂與查核紀錄。

我的 AI 小 Tips｜資訊不足時先追問

適用任務尚未確定如何完整描述複雜任務時。

使用前準備先說明你目前的目標與已知資訊。

若資訊不夠清楚，先用選項式問題向我確認，必要時繼續追問；不要自行假設，確認足夠後再開始。

人工查核：AI 的追問只能協助釐清；研究範圍與最後選項仍由你決定。

Connector 任務｜執行 PubMed 搜尋

適用任務已開啟 PubMed Connector，準備執行初步檢索。

可替換欄位P、I、O、是否加入研究設計限制、輸出筆數。

依照我的 PICO 建立 PubMed search string，實際執行搜尋，告訴我總共找到幾篇。

P：成年 ICU 病人

I：家屬參與照護或彈性探視

O：譫妄發生率

先不要加入研究設計限制。列出前 10 筆的 PMID、Title、Year，並保留完整可重現的 PubMed search strategy。

請用 MeSH + free-text terms 搜尋；若 MeSH 尚未核對，請明確標示「待官方核對」。

人工查核：展開工具呼叫區塊，比對實際送出的 query 與回傳 PMID；再把策略放回 PubMed 官網實測。

共同案例｜PubMed 檢索字串

適用任務在 PubMed 官網逐塊實測共同案例。

可替換欄位已核對的 MeSH、自由詞與概念塊。

("Intensive Care Units"[MeSH Terms] OR "intensive care unit"[tiab] OR ICU[tiab])

AND

("Family"[MeSH Terms] OR "family participation"[tiab] OR "family involvement"[tiab] OR "family engagement"[tiab] OR "family-centered care"[tiab] OR "flexible visitation"[tiab] OR "family visitation"[tiab])

AND

("Delirium"[MeSH Terms] OR delirium[tiab])

人工查核：MeSH Terms、欄位標籤與同義詞需回官方資源確認；記錄官網執行日期與結果數。

Prompt 1｜臨床觀察 → PICOS

適用任務把尚未定案的臨床觀察轉成可討論的 PICOS。

可替換欄位臨床族群、介入、情境與預期結果。

【背景】
我是臨床護理人員，想探討：成年 ICU 病人接受家屬參與照護或較彈性的探視方式，是否能降低住院期間譫妄。

【任務】
把臨床問題整理成 PICOS 候選，並協助我辨識研究範圍尚未定案之處。

【限制】
不要補寫我沒有提供的病人特徵、家屬參與內容、比較組或結果。每一欄標示「已知／合理候選／待確認」。

【輸出】
1. PICOS 表：定義、目前依據、可能過寬／過窄。
2. 一句可回答的研究問題。
3. 最影響研究範圍的 3 個追問。

【不確定性處理】
資料不足時寫「待確認」，並說明需要我補充什麼；不要自行替我定案。

人工查核：確認 AI 沒有新增你未提供的族群、介入或比較組；逐欄決定哪些候選可採用。

Prompt 2｜PICOS → 關鍵字與 MeSH 候選

適用任務PICOS 已有初步定義，準備建立 PubMed 概念塊。

可替換欄位P、I、C、O、S 與優先研究設計。

【背景】
已定義：P＝成年 ICU 病人；I＝家屬參與照護或彈性探視；C＝常規照護、標準或限制探視；O＝譫妄發生率，次要可看持續時間、嚴重度或無譫妄天數；S＝優先 RCT。

【任務】
為 PubMed 建立關鍵字候選表。先判斷哪些 PICOS 元素適合作為主要檢索概念。

【限制】
MeSH 只能標示為「候選」，提醒我回 MeSH Database 核對；不要虛構 scope note、結果數或文獻。不要自行加入語言、日期或年齡限制。

【輸出】
每一概念塊列：MeSH 候選｜title/abstract 自由詞｜拼字變體｜truncation｜可能造成漏失或雜訊的詞。最後列建議測試順序。

【不確定性處理】
不確定是否為官方 MeSH 時，標「需核對」；可能歧義的詞另列，不直接放入正式策略。

人工查核：到 MeSH Browser 核對正式 Heading、Scope Note 與 Entry Terms，再決定採用、修正或不用。

Prompt 3｜建立可實測的 PubMed 檢索式

適用任務MeSH 與自由詞已核對，準備組合正式策略初稿。

可替換欄位資料庫、概念塊、欄位代碼與已核對詞彙。

【背景】
我要將已核對的 ICU、family involvement／flexible visitation、delirium 三個概念塊組成 PubMed 檢索式初稿。

【任務】
使用同義詞 OR、概念塊 AND，產出可直接貼入 PubMed 的檢索式，並提出逐步測試方案。

【限制】
只使用我提供或已標示核對完成的 MeSH 與自由詞；欄位標籤使用 [Mesh] 與 [tiab]。未經同意不要加入 RCT、日期、語言或 Humans filter。不要捏造結果數。

【輸出】
1. 三個概念塊。
2. 完整檢索式。
3. 語法檢查清單。
4. 從單塊、兩塊到三塊的測試順序。
5. 若找不到已知種子文獻時的除錯步驟。

【不確定性處理】
任何尚未核對的詞都在策略下方列為「待核對」，不要混入看似已定案的正式字串。

人工查核：在 PubMed 逐塊執行，記錄結果數並確認已知種子文獻；換資料庫時重新翻譯語法。

Prompt 4｜題名摘要初篩

適用任務已有納排標準與包含題名、摘要、識別碼的紀錄。

可替換欄位PICOS、納排標準、資料庫、日期與紀錄內容。

【背景】
研究問題與納排標準如下：〔貼上已定案 PICOS 與納排標準〕。以下紀錄來自〔資料庫／工具與日期〕，包含題名、摘要與識別碼。

【任務】
只依題名與摘要做初篩；逐筆判斷 P／I／C／O／S，並保留可查核理由。

【限制】
只有至少一項納入條件「明確不符合」時才能排除。摘要沒寫、語意含糊或需要全文才能確認時，一律標「待確認」。不要利用外部記憶補資料。

【輸出】
表格欄位：紀錄編號｜題名｜P｜I｜C｜O｜S｜總判定（納入／排除／待確認）｜單一主要理由｜支持判斷的摘要原文｜需要人工查核之處。

【不確定性處理】
缺摘要、引用錯配或識別碼不一致時標「書目待確認」，不得直接排除。最後彙總三類數量。

人工查核：核對書目身分、支持判斷的摘要原文與研究設計；「沒提到」不能當成排除理由。

Prompt 5｜全文閱讀與資料彙整

適用任務已通過初篩，並能提供合法取得的全文或指定來源。

可替換欄位需要萃取的研究欄位、效果指標與來源範圍。

【背景】
以下為已通過題名摘要初篩的全文。請只依我提供的 PDF／來源進行資料定位與初步結構化。

【任務】
萃取並整理：研究設計、場域、樣本數與特徵、PICOS、介入細節、比較組、結局與測量時間點、效果估計值、95% CI／p 值、不良事件、作者陳述的限制。

【限制】
每一格都附原始頁碼、表格、圖或段落。不得把摘要推論成全文結果，不得換算或合併作者未提供的數值，不得自行判定偏誤風險。

【輸出】
建立一列一研究的證據表；效果值保留原單位、分母與時間點。另列「需要人工再算／再確認」清單。

【不確定性處理】
沒有報告寫「未報告」；文字無法判定寫「無法判斷」；數值衝突時同時列出兩處原文位置，不替研究者選一個。

人工查核：逐格回到頁碼、表格、圖或段落；特別核對效果值、單位、分母、時間點與作者限制。
